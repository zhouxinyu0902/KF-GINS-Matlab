## 四、几个重要的结构原则

### 1. 原始代码与修改代码分开

不要继续把修改后的函数覆盖或混放在源项目目录中。建议明确划分：

```text
platform/upstream/     原始代码，原则上只读
platform/modified/     对原始核心函数的修改版本
common/                你自己形成的通用算法
projects/              仅服务于特定专题的函数
```

这样以后能够回答两个关键问题：

- 这个函数是否来自原始项目？
- 如果修改过，与原始版本有什么区别？

### 2. 公共函数与专题函数分开

判断标准可以采用：

- 被两个及以上专题调用：进入 `common/`；
- 只服务一个实验：留在对应 `projects/<topic>/functions/`；
- 只是临时绘图或一次性数据处理：进入专题的 `scripts/`；
- 已经不用但需要保留：进入 `archive/`。

不要一开始把 `function_zxy/` 的所有函数都认定为公共函数。里面部分函数很可能绑定了特定状态维数、全局变量或数据格式，本质上还是专题函数。

### 3. 每个专题采用相同内部结构

建议统一成：

```text
topic_name/
├─ README.md
├─ config/
├─ scripts/
│  ├─ preprocess/
│  ├─ run/
│  └─ postprocess/
├─ functions/
├─ tests/
├─ input/          # 小型配置或示例输入
└─ output/         # 默认不提交大结果
```

其中：

- `README.md`：专题目的、理论方法、入口和运行顺序；
- `config/`：路径、噪声、初值和实验开关；
- `scripts/run/`：可以直接运行的主程序；
- `functions/`：该专题私有函数；
- `tests/`：小数据验证；
- `output/`：结果，不和源代码混放。

### 4. 数据和算法逐步分离

`MEMS_RANGE/`、`惯导实验数据/`、`潜标位置标定/` 最大的问题不是目录名称，而是算法、原始数据、中间结果和图片混合。

推荐最终形成：

```text
datasets/mems_range/experiment_01/raw/
datasets/mems_range/experiment_01/processed/
datasets/mems_range/experiment_01/metadata.md

projects/experimental/mems_range_azimuth/scripts/
projects/experimental/mems_range_azimuth/functions/
```

数据目录最好增加 `metadata.md`，记录：

- 采集日期和设备；
- IMU 型号和采样率；
- 坐标系；
- 每列含义及单位；
- 起止时间；
- 对应的实验脚本；
- 是否允许修改。

## 六、我最推荐的近期重点

不必立刻追求“目录完全漂亮”。第一轮整理只完成三件事就已经很有价值：

1. 明确原始平台、公共扩展和专题代码的边界；
2. 把当前工作集中到 `projects/active/`；
3. 为每个专题补充一个 README，说明“研究什么、运行哪个文件、依赖哪些数据、目前得到什么结论”。

这比直接大规模移动文件更安全。尤其是仓库中大量脚本含绝对路径，而且不同目录可能存在同名函数；一次性重排后，MATLAB path 的函数遮蔽顺序可能改变，程序即使能运行，也可能悄悄调用了错误版本。最稳妥的是按专题逐个迁移并保存对比结果。
